helios docs

Everything you need to install helios, read your stats, and sync them to your site.

Quick start

1. Install helios

On macOS, Linux, or Git Bash on Windows:

curl -fsSL https://raw.githubusercontent.com/part-avocado/helios/main/install.sh | sh

On Windows, in PowerShell:

irm https://raw.githubusercontent.com/part-avocado/helios/main/install.ps1 | iex

2. Answer the setup questions

The installer finishes by running helios setup. It lists the tools it found and asks before each change:

  • Keep Claude Code transcripts past 30 days.
  • Add helios's hooks or plugin to Claude Code, Codex, Amp, OpenCode, Copilot, and Cursor.

Saying yes to each is the recommended setup. helios setup explains every question.

Then use your tools as you normally do.

3. See your time

Just this computer

Run helios for your timeline and project totals, or helios dashboard for charts in your browser. You need no account, and nothing leaves your computer.

On the website

To see every computer's hours in one place:

  1. Open the dashboard and sign in with Hack Club. Your first sign-in creates your account.
  2. Run the command the dashboard shows. Your terminal prints a code; type it on the site.
  3. Do the same on each computer you code on. Each one syncs by itself from then on.

Install

macOS, Linux, and Git Bash on Windows

curl -fsSL https://raw.githubusercontent.com/part-avocado/helios/main/install.sh | sh

Windows (PowerShell)

irm https://raw.githubusercontent.com/part-avocado/helios/main/install.ps1 | iex

What the installer does

  1. Downloads the right binary for your computer.
  2. Checks it against the release's checksums.txt. This needs sha256sum, shasum, or openssl. Without one of them, it installs nothing.
  3. Installs it to ~/.local/bin, or %LOCALAPPDATA%\Programs\helios on Windows. No admin rights are needed.
  4. Adds that folder to your PATH.
  5. Runs helios setup.

When helios starts working depends on which command you ran:

  • The first command writes the PATH change to your shell's profile. Open a new terminal before you run helios yourself.
  • The PowerShell command also adds the folder to the window you installed from, so helios works there straight away. Restart any other terminal that was already open.

Updating

CommandWhat it does
helios updateInstalls the latest version. Running the install command again does the same.
helios update -checkOnly says whether a newer version is out.
helios update v0.5.0Installs one version in particular, even an older one.

helios update and the installer both run helios setup again with the new version, to bring hooks and plugins up to date.

Automatic updates

Once a day, a background sync checks for a newer release. When there is one, helios prints one line to say so. It installs nothing by itself.

To have helios update itself, run helios update -auto on. From then on, the daily check:

  • installs each new release once it matches the release's checksums and runs as that version;
  • keeps the version it replaced beside it, with .old on the end;
  • says that it updated, for three days.

After an update like this, run helios setup to bring hooks and plugins up to date. To stop automatic updates, run helios update -auto off.

The checksums come from the same release as the binary. So auto-update trusts GitHub and helios's release workflow as much as the installer does.

Installer options

These optional environment variables change what the installer does:

VariableEffect
HELIOS_VERSIONInstall a specific release, such as v0.1.0.
HELIOS_INSTALL_DIRInstall to another folder.
HELIOS_NO_MODIFY_PATHDon't edit your shell profile or PATH. Print the line to add instead.
HELIOS_NO_SETUPDon't run helios setup afterwards.
HELIOS_CLOUDSet to 1 in a cloud environment, Codespace, or dev container. It sets up Claude Code and every other tool found, without asking. Also set HELIOS_SERVER and HELIOS_KEY there; see Claude Code in the cloud.
HELIOS_BASE_URLDownload the binary and checksums.txt from this URL, such as a mirror, instead of the GitHub release.

Install with Go

With Go 1.25 or later you can also run go install github.com/part-avocado/helios/cmd/helios@latest.

helios setup

helios setup first shows every place helios looks for logs, how many sessions it found, and when the newest one is from.

Then it offers each of these changes, one at a time:

  • Keep Claude Code history. Claude Code deletes transcripts after 30 days by default. Setup offers to raise cleanupPeriodDays to 3650.
  • Add Claude Code hooks, which record your work as it happens. See Claude Code.
  • Add Codex hooks. See Codex.
  • Add the Amp plugin. See Amp.
  • Add the OpenCode plugin. See OpenCode.
  • Add Copilot and Cursor hooks. See Copilot and Cursor.
  • Add Antigravity hooks. See Antigravity.

Note

Setup never changes anything without a yes. It keeps your own hooks and settings, saves a backup the first time it edits a file, and is safe to run again. Pass -yes to accept everything without prompts.

Set up one tool only

Name the tool: helios setup claude, codex, amp, opencode, antigravity, copilot, or cursor. You can name more than one.

Setup offers the Amp plugin even on a computer where Amp isn't installed yet, so the plugin is in place when Amp is.

Set up cloud sessions

Cloud sessions of a repository, such as Claude Code on the web or Codex cloud, need hooks in the repository itself. Run helios setup -project in the repository instead. See Remote sessions.

The report

Run helios to see the last 7 days, or helios -since 30d for longer. It prints two tables: the first lists your work blocks, and the second totals each project.

ColumnMeaning
ENGAGEDTime you were plausibly involved. This is the number that matters.
SPAN / SESSION TIMEWall-clock time from first to last activity, for comparison.
PROMPTSPrompts you sent that counted.
SKIPPEDPrompts that earned no time.
TOKENS IN/OUTTokens the model read (cached ones included) and wrote.
TOOLSWhich AI tools you used in that block.

Two flags change how the report comes out:

  • -l (or --live) keeps it on screen and updates it as you work. Press Ctrl-C to quit.
  • -json prints the report as data.

How a project is named

helios names a project by the first of these that it has:

  1. its git remote;
  2. its repository folder;
  3. its working folder.

So the same repository adds up across tools and clones.

A folder inside your home folder is written starting from it, as ~/code/app, and your home folder itself is written as home. That way the project key your site sees doesn't name your account on the computer.

Older versions of helios used the full folder path as the key. Projects recorded that way show up twice on your site: the old key holds the time from before the change, and the new key holds the time since. No time counts twice.

The dashboard

The dashboard shows an activity heatmap, daily totals, projects, tools, and recent work blocks. You can open it on the website, with an account, or on your computer, without one.

Reading the graphs

The graphs are interactive:

  • Hover a day, bar, or tool for the details.
  • Click a day on the heatmap, or a bar, to list that day's work blocks. On the yearly chart, a bar lists a week.
  • Click a project in the table to see only that project. Every number and chart follows it. Click it again, or the chip at the top, to clear it.

On the website, with an account

The dashboard on the website adds up the hours from every computer you code on. Only you and your server's reviewers can see it. Your public profile shows a summary to anyone.

  1. Open the dashboard and sign in with Hack Club. Your first sign-in creates your account.
  2. Run the command the dashboard shows. Your terminal prints a code; type it on the site. That connects this computer to your account. Do the same on each computer you code on.
  3. Keep working. The page fills in as soon as the first sync arrives. helios syncs again each time a reply finishes in Claude Code or Amp, or you stop one. Run helios sync to update it right away.

Projects

The Projects page lists every project you've worked on. Open one to see that project on its own. A project's page also has its settings:

  • Public: whether your public profile names it.
  • The GitHub repositories linked to it, which you can add or remove.

Settings

Settings has the rest:

PaneWhat it's for
SetupWhat to run to connect another computer, and your sync keys. A sync key only uploads stats. Each computer gets its own, and cloud sessions (Claude Code in the cloud, Amp threads) get one named "Cloud sessions". Revoke one and only it stops working.
ComputersEach computer that syncs to you and when it last did. Remove one to drop its hours.
DataUpload a stats file from a computer that can't reach the website, or download a copy of everything the site holds about you. Make the stats file with helios export -o stats.json, and upload it within 7 days.
AccountYour name, Slack ID, and member-since date from Hack Club Auth, signing out, and deleting your account. Deleting removes every computer and all of your stats from the site.

You can sign out from the sidebar, or on a narrow window from the menu at the top right.

A computer syncs to one account. To move it to another, remove it under Computers first.

On your computer, without an account

Run helios dashboard to open the same charts with live data from this computer, refreshed every 30 seconds. It runs on localhost only and refuses requests from other sites, so your stats never leave your computer.

Your public profile

Every account has a public profile at /@handle, which anyone can open without signing in.

It shows your handle, the month you joined, your hours in the past year, a year of days, and your projects. It never shows your name, your Slack ID, or a folder on your computer.

Which projects it names

  • A project that is a repository on a public host, such as github.com/you/site, is public by default. The profile names it and links to its repositories.
  • Any other project is only counted, as one of your other projects, until you make it public.

Turn Public on or off on each project's page.

Your handle

Each account starts with a neutral handle, such as u-3f9a0c12b4d1, never one made from your name. When you change it, the old address stops working.

Profile settings

Under Settings, Profile, you can:

  • change your handle;
  • make the whole profile private;
  • copy a badge of your hours to paste into a README, linked to your profile.

A private profile answers "no such profile", as a banned or deleted account does. So its address doesn't say that the account exists.

Verification keys

Every sync and export carries a verification key. It is an Ed25519 signature, made by your account, over the report's numbers, the time it was made, and the time it expires. Change one minute of engaged time, the account, or a date, and the key no longer matches.

The website refuses a report that:

  • has no key, or a key that doesn't match its contents;
  • is more than 7 days old, so an old or reused file can't stand in for current numbers;
  • claims to be made in the future, or contains activity after the time it was made.

Each computer's key is created the first time it syncs or exports. It is kept in helios's data folder as account.key. Settings lists your computers by the ID of that key, such as td-4283292a8f76.

Warning

Verification proves a file wasn't edited after helios export made it. Because the account key lives on your computer, a file alone can't prove the numbers are real. For hours that count, sync.

Tokens

Where token counts come from depends on the tool:

ToolWhere its counts come from
Claude CodeThe usage record it saves with each response. A response that's written several times, or copied into a resumed session, counts once.
CodexThe usage record it saves with each response. Counts are taken from the increase in its running totals.
AmpThe usage Amp hands the helios plugin when a turn ends. This starts with helios v0.6.0, so Amp turns recorded before that show no tokens.

Claude Code

helios counts Claude Code in two ways: it reads the transcripts Claude Code saves, and, with hooks installed, it records each event as it happens.

Transcripts

helios reads transcripts from $CLAUDE_CONFIG_DIR (which may list several folders), ~/.claude, and ~/.config/claude.

It tells your prompts apart from tool results, compaction summaries, background notices, and subagent activity. Subagent transcripts are ignored: their time, tokens, and edits do not count.

Hooks

With hooks installed, Claude Code runs helios hook claude-code when a session starts or ends, when you send a prompt, and when Claude finishes.

Each run adds one line to a local journal. The line holds the time, session, folder, and the prompt's word counts and fingerprint, never its text. If Claude Code deletes a transcript, the journal still has that session.

Claude Code in the cloud, Codespaces, and remote machines

Which setup fits depends on whether the machine lasts.

A machine you keep, such as an SSH box

Install helios there and connect it like any computer. With no browser on it, you have three ways to connect:

  • A code. Run helios login -server https://your-site -no-open. It prints a code to type on the site from any other device.
  • A sync key. Make one under Settings on the site and run helios sync -server https://your-site -key tdk_….
  • Environment variables. Set HELIOS_SERVER and HELIOS_KEY in the box's environment. This needs no login. Hooks then send each event as it happens and sync in the background, just as after a login.

The box keeps its own journal, is listed as a computer of its own, and syncs in the background.

A machine that goes away: cloud sessions, Codespaces, dev containers

Transcripts and the journal in a cloud container disappear with it. So there helios sends each hook event straight to your site instead of keeping a journal. This is called cloud mode.

Cloud mode is on when both of these are true:

  • HELIOS_SERVER and HELIOS_KEY are both set.
  • One of CLAUDE_CODE_REMOTE, CODESPACES, or HELIOS_CLOUD is 1 or true. Claude Code on the web sets the first by itself, and GitHub Codespaces sets the second.

To set it up:

  1. On the site, make a key under Settings.
  2. Add two secrets to the environment: HELIOS_SERVER (your site) and HELIOS_KEY (the key). For Codespaces, add them as Codespaces secrets of your account or the repository. Also set HELIOS_CLOUD=1, unless the environment sets CLAUDE_CODE_REMOTE or CODESPACES itself.
  3. Add this to the environment's setup script. For a Codespace or dev container, add it to postCreateCommand in devcontainer.json:
curl -fsSL https://raw.githubusercontent.com/part-avocado/helios/main/install.sh | HELIOS_CLOUD=1 sh

That line installs helios, creates ~/.claude if no Claude Code folder exists, and adds the hooks of every tool it finds, without asking.

To check, run helios doctor. It says whether cloud mode is on, and which secret is missing when it is not.

Or commit the hooks to the repository

If you can't edit the environment's setup script, run this once in the repository, on your own computer, and commit the file it writes:

helios setup claude -project

It adds hooks to the repository's .claude/settings.json, keeping whatever is there. You still add the two secrets to the environment.

What the committed hooks do depends on where they run:

  • Where HELIOS_KEY is set, the session's start installs helios if it is missing. Each prompt and reply then runs helios hook claude-code -project, found on PATH or in ~/.local/bin.
  • Where HELIOS_KEY is not set, they do nothing. Nothing is installed or recorded for teammates who don't use helios.
  • Where your own Claude Code settings already have helios's hooks, they also do nothing, so each event is recorded once. That is the case on your own computer, or on a machine the setup script set up.

If the repository's hooks don't end in -project, an older helios added them, and those don't check for your own hooks. Run helios setup claude -project again and commit the change.

To take the hooks out again, run helios setup claude -project -remove-hooks.

What cloud mode sends

Each event goes to your site as it happens. It holds what a journal line holds: the time, tool, session, and a prompt's word counts and fingerprint, never its text.

The site can't look the folder up later, so the event also carries:

  • the repository, named from its origin remote, without any sign-in the remote holds;
  • the folder's path inside the container, such as /home/user/repo.

A reply's end also carries the tokens and lines of that turn, read from the transcript, and your commits in the repository since the last one.

No sync runs there, and no account key is made.

How cloud sessions are counted

  • One computer. Cloud sessions all count as one computer, called "cloud", however many containers ran them. So a new container never adds a computer to your list.
  • No clock correction. That computer's records are used at the times the container gave them.
  • No time zone of its own. Its days are counted at the UTC offset your own computers pinned for your account.
  • No subagents. Subagent activity is not counted there either.

Codex

Logs

helios reads Codex's session logs, called rollouts, from $CODEX_HOME or ~/.codex. It looks in both sessions and archived_sessions, and reads compressed .jsonl.zst files too. It handles both the older and the current (0.147 and later) log formats.

Subagent and reviewer sessions never count as your prompts.

Hooks and notify

helios setup also adds two things to Codex:

  • Hooks, in ~/.codex/hooks.json. With them, each prompt and turn end reaches your site as it happens.
  • A notify line, in ~/.codex/config.toml. It syncs when a turn ends. If your config.toml already has a notify program, helios leaves it alone.

Important

Codex skips new hooks until you trust them. Open Codex, run /hooks, and trust helios's.

The notify line needs no trust step, so Codex syncs on its own either way.

Remote machines and the cloud

On an SSH box, Codespace, or cloud container, set helios up as for Claude Code. Two things differ for Codex:

  • The hooks still need the trust step, which a setup script can't do. Run /hooks once in each new container, or they are skipped.
  • Until then, only notify runs, and it reports turn ends, not prompts. In cloud mode there is no sync to read the rollouts later. So a container whose hooks were never trusted earns no time.

Amp

Amp keeps threads on its servers, so helios can't read them from your computer. Instead, helios setup (or helios setup amp for Amp alone) offers to write a plugin to ~/.config/amp/plugins/helios.ts.

The plugin records when a thread starts, when you send a prompt, and when Amp finishes. It writes to the same journal as the Claude Code hooks.

New Amp threads load the plugin automatically. In threads that are already open, run plugins: reload.

Threads in Amp's cloud

Threads you start in the Amp app or on ampcode.com run in Amp's cloud, not on your computer, so that plugin can't see them. A second plugin, helios-cloud.ts, counts them. It goes in your personal Amp plugins, which Amp loads in every cloud thread.

Set it up

  1. On your helios site, open Settings, Setup, and choose Amp under “Check your tools”.
  2. Make a sync key with Make a key for Amp, under the prompt shown there. It shows once, and is listed under your sync keys as "Cloud sessions".
  3. Paste the prompt into any Amp thread. Amp adds the plugin and two values to its Secrets & Env Vars settings: HELIOS_SERVER, your site's address, and HELIOS_KEY, the sync key. Amp asks you for the key in a private dialog, so it stays out of the thread.

What the plugin does

In a cloud thread, the plugin downloads helios and checks it against the release's checksum. It then runs helios when you send a prompt and when Amp finishes. Each run sends your site one line:

  • Every line holds the time, thread, folder, repository, and the prompt's word counts and fingerprint, never its text.
  • When Amp finishes, the line also holds the tokens the turn used and the lines its file edits added and removed, never the code.

Your site keeps these lines for a year.

At the end of each turn helios also sends your commits in the thread's repository, as helios sync does on a computer. So they show in the review app's graphs and can be checked against GitHub.

How cloud time is counted

No computer of yours is needed. When Amp finishes a turn or you stop it, the helios in that thread:

  1. reads all of your cloud lines back from your site;
  2. counts them with the same rules as everything else;
  3. syncs the result.

Threads that ran side by side are counted together, so their overlap counts once.

Your cloud threads show up as one entry under Settings, Computers, named “Cloud sessions”.

Note

Cloud time reaches your dashboard when Amp finishes a turn or you stop it. Its days are split at midnight UTC, because a cloud thread doesn't know your time zone.

Threads on your Mac

The Mac app's threads can also run on your Mac instead of the cloud. Open the app's App Settings, Runner, turn it on, and pick “This Mac” when you start a thread. Those threads are recorded by the first plugin.

Set up with a prompt

The dashboard's setup steps include a prompt to paste into Amp or Claude Code, with your server already filled in. The agent then:

  1. installs helios;
  2. runs helios setup -yes, to add the hooks and the plugin without stopping to ask;
  3. runs helios login and shows you the code to type on the site;
  4. shows you the result.

-yes is what lets an agent finish setup, since setup otherwise asks before changing any settings and an agent can't answer. The prompt holds no key, so nothing secret ends up in that thread.

Copilot and Cursor

helios setup adds hooks for both tools:

ToolWhat setup does
GitHub Copilot CLI and VS Code's Copilot agentWrites ~/.copilot/hooks/helios.json.
CursorAdds helios's hooks to ~/.cursor/hooks.json, keeping any hooks of your own. Restart Cursor to load them.

Neither tool keeps transcripts helios can read. So their time comes from the hooks alone, and only reaches your site once this computer is set up with helios sync.

Copilot CLI's hooks name no session. So helios names one after the folder it runs in: a hash of its path, never the path itself.

Remote machines and the cloud

On an SSH box, Codespace, or cloud container, set helios up as for Claude Code.

With HELIOS_CLOUD=1 the installer sets up Copilot and Cursor too, where their ~/.copilot or ~/.cursor folder exists. If Copilot has not made its folder yet, run helios setup -yes copilot, which makes it.

Their hooks then send each event straight to your site.

OpenCode

helios setup (or helios setup opencode) writes a plugin to ~/.config/opencode/plugins/helios.ts. When $OPENCODE_CONFIG_DIR is set, it goes in that folder's plugins folder instead. OpenCode 1 and 2 both load it.

The plugin runs helios hook opencode when you send a prompt and when a turn ends, whether it finished, failed, or was stopped. It records the time and folder, never the prompt text.

Two limits:

  • Prompts in a subagent's session come from the agent, so they aren't counted as yours.
  • OpenCode keeps its history in a database helios doesn't read, so time before the plugin was added doesn't count.

Antigravity

helios setup (or helios setup antigravity) offers to add a helios group to Antigravity's global hooks file, ~/.gemini/config/hooks.json. The App, the CLI, and the IDE all read that file. Your other hook groups are kept.

What the hooks record

The group runs helios hook antigravity on three events:

EventRecorded as
SessionStartthe session starting
PreInvocation, on an execution's first model callyour prompt, scored for effort and repeats, then thrown away
Stopthe turn ending

Two things to know:

  • Antigravity runs PreInvocation before every model call. Only the first call of an execution follows a prompt of yours, so helios skips the rest.
  • Antigravity's hooks report no tokens, so its turns show no token counts.

Each hook prints {}, which is what Antigravity needs from a hook that changes nothing.

Check that the hooks loaded

In the app, open the agent side panel, then Customizations, then Hooks. In the CLI, run /hooks.

Remove the hooks

helios setup -remove-hooks antigravity takes the group out again.

For Antigravity on a remote machine, see Remote sessions.

Remote sessions

Some agents work on a machine that goes away: Claude Code on the web, Codex cloud tasks, a Codespace, or OpenCode or Antigravity on a remote VM. There helios runs in cloud mode.

Cloud mode in short

  • Each hook event goes straight to your site.
  • Every cloud machine counts as one computer, called "cloud".
  • It is on when HELIOS_SERVER and HELIOS_KEY are set, together with one of HELIOS_CLOUD=1, CLAUDE_CODE_REMOTE=true (Claude Code on the web sets it), or CODESPACES=true.

Claude Code in the cloud describes it in full.

Commit hooks that install helios

A cloud machine starts from your repository and has no helios of its own. So commit hooks that install it:

helios setup -project            # Claude Code, Codex, Antigravity, and OpenCode
helios setup codex -project      # or only the tools you name
FileFor
.claude/settings.jsonClaude Code on the web
.codex/hooks.jsonCodex cloud
.agents/hooks.jsonAntigravity on a remote machine
.opencode/plugins/helios-project.tsOpenCode on a server

Your own settings in those files are kept.

How the committed hooks behave:

  • Without HELIOS_KEY, they do nothing. So nothing changes for a teammate who doesn't use helios.
  • At a session's start, they install helios if it is missing. They use the installer, which checks the release's checksums.
  • On your own computers, they don't record twice. The Codex, Antigravity, and OpenCode hooks record only in cloud mode; on your own computers, the hooks helios setup adds there record the session. Claude Code's stand down where your own settings already run helios's hook.

Set up an environment

  1. Run helios setup -project in the repository, then commit and push.
  2. Under Settings, Setup, on your site, make a sync key named after the environment.
  3. In the environment's settings, set HELIOS_SERVER to your site and HELIOS_KEY to that key. Outside Claude Code on the web and Codespaces, also set HELIOS_CLOUD=1.
  4. Let the environment reach your site, and github.com, raw.githubusercontent.com, and objects.githubusercontent.com, which it needs to install helios. For Claude Code on the web, use Limited network access and add your site under Allowed domains.

Warning

Anyone who can use the environment can read its variables. A sync key can only upload stats, and you can revoke it under Settings at any time.

Notes for each tool

WhereWhat to know

Codex cloudCodex runs a repository's hooks once they are trusted. Check your dashboard after the first task, since a cloud task may not run them.
OpenCode on a serverThe plugin runs in the opencode serve process. Set the variables where it starts.

A remote machine you keep

A remote machine you keep can instead run the installer and helios login, like any computer.

Remove the hooks

helios setup -project -remove-hooks takes the hooks out again.

Connectors

Chat apps have no hooks, but they can add a connector: a remote MCP server. Your site is one, at /mcp.

Add it to a chat app, and that app's chats add to your hours. It works with Claude on the web (claude.ai), the Claude desktop and mobile apps, ChatGPT, or any app that takes a remote MCP server with OAuth.

Add it

  1. In Claude, open Settings, then Connectors, and choose Add custom connector. Other apps have a similar place.
  2. Give it your site's address followed by /mcp, such as https://helios.example/mcp. Other apps ask for the same address.
  3. The app sends you to your site, which shows what the connector will do. Choose Allow.

Your site makes the app a sync key named after it, such as "Claude connector". To disconnect the app, revoke that key under Settings, Setup.

What it records

The connector gives the model two tools:

ToolWhat it does
helios_logThe model calls it with start when it begins a reply and end when it finishes. Each call is one record, a prompt or a turn end, like the ones a harness's hooks send.
helios_statsReads your hours, per day and per project, to answer questions such as "how much did I work this week?"

A record carries:

  • the conversation, as a digest of the name the model gives it;
  • the word count of your message;
  • the repository, if you name one.

It never carries your message or the reply.

How chat time counts

  • Time. The site stamps each record with the time it arrives, so a chat's time is witnessed like any other. It is credited by the same rules as any other tool's.
  • Tool name. A chat counts under the app's own name, such as claude-ai or chatgpt, so reviewers can tell chat time from time in coding tools.
  • Project. Chats name no project unless the model passes a repository, such as github.com/owner/name. Without one, they show as the app's chats.

Note

The model decides when to call the tools. A chat in which it doesn't call them adds nothing. If yours skips them, ask it to log the conversation with helios.

Add your own harness

Any tool can report to helios. Run helios hook <tool> with one JSON object on stdin:

{"session_id": "abc123", "cwd": "/home/me/project", "hook_event_name": "prompt", "prompt": "add a login page"}

The tool name is yours to choose, from lowercase letters, digits, and dashes.

FieldMeaning
session_idRequired. One conversation or thread.
hook_event_nameRequired, unless you pass -event instead. One of prompt, turn_end, session_start, session_end, or edit.
cwdThe folder, which names the project by its git remote. Only the project key leaves the computer.
promptFor prompt events. It is scored for effort and repeats on the computer, then thrown away. Its text is never stored or sent.
tokens_in, tokens_out, lines_added, lines_removedOptional, on turn_end or edit.

What helios does with an event

helios writes the event to the local journal. Once the computer is connected, it also sends the event to your site as it happens.

It never gets in your tool's way:

  • It always exits 0.
  • For a tool of your own, it prints nothing on stdout. A built-in harness gets the one reply it needs there, such as Cursor's {"continue":true}.
  • If an event can't be written, the reason goes to stderr.

Test an adapter

helios hook -check <tool> prints the record a payload would make and writes nothing.

Connect your tool

  • A tool with a hooks file in Claude Code's shape: point its prompt and stop hooks at helios hook mytool.
  • A tool with plugins: run the same command from the plugin, as helios's own Amp plugin does with helios hook amp.

Lines of code

What helios sends about commits

When a computer syncs, helios also sends your site one record for each commit of yours, in each project with a git remote. A record holds the commit's SHA, author time, and lines added and removed, never its message or code.

Commits earn no time.

Checking commits against GitHub

Your profile links a public repository's latest commits. Once an hour the site asks GitHub which of them exist, so a reviewer can spot a claimed commit that GitHub doesn't have.

For each commit GitHub has, the review app also:

  • shows the GitHub account it is linked to;
  • marks it if its claimed time differs from GitHub's author date. The SHA pins that date, so a difference means the time was changed after the commit was made.

A private repository's commits are shown as not checked.

The check needs a GITHUB_TOKEN secret on the Worker. Without one, the review app says so.

Lines in the report

For each project the report shows three counts:

ColumnMeaning
AGENT LINESThe lines agents changed.
KEPTHow many of the lines agents added later turned up in your commits.
COMMITTEDThe lines your own commits added.

The code itself is not kept.

Sync

helios sync sends your records to your account on the site. There is one record for each prompt and each turn end. A record holds its time, word counts, tokens, and lines, never its text.

The first sync sends the past year. Later ones send only what changed.

Connect a computer

Before a computer can sync, connect it:

helios login -server https://your-site
  1. helios prints a code such as BCDF-GHJK and opens the site's connect page.
  2. Sign in and type the code.
  3. Check that the computer ID on the page matches the one in your terminal.

helios then saves a sync key for this computer and syncs. Each computer gets its own key. They are listed under Settings, Setup, by computer ID, so you can revoke one without touching the rest.

A code lasts 10 minutes and works once. It has to be typed, not followed from a link, so nobody can send you a link that connects their computer to your account.

Warning

Never type a code someone sent you. Allowing a code gives that computer a sync key to your account. The connect page says when and from where each code was asked for.

A computer with no browser

Make a sync key for it under Settings, Setup. Then run this on that computer:

helios sync -server https://your-site -key tdk_…

After the first sync

helios remembers the server and the key, so later it's just helios sync.

Hooks also sync in the background when a reply finishes or you stop one:

  • Amp reports a stopped reply at once.
  • Claude Code runs no hook when you stop a reply, so that sync happens at your next prompt or when the session closes.
  • Codex syncs through its notify program when a turn ends.

The key only sends records. It can't read or change your account or settings. If the server answers that it needs your sync key, run helios login again.

Who can see your stats

On the website, your stats are visible to you and to reviewers. Beyond that, anyone can see what your public profile shows.

  • A reviewer sees, for each project, your total and a timeline of your work blocks: when each started and ended, with its prompts, tokens, and lines changed.
  • Neoadmins and superadmins see everything you synced.

Deleting your account, under Settings, removes your stats. Admins keep your Slack ID and a record of what your computers reported, without project names.

Who credits your hours

helios itself credits nothing. Programs that pay or credit hours read your time through the Stats API and decide what counts.

To host the site yourself, see Running a server.

Running a server

The site is one Cloudflare Worker. It uses:

  • a D1 database, for summaries;
  • an R2 bucket, for every report and per-prompt record;
  • a Durable Object per account, which takes records as they arrive and pushes them to open dashboards.

The website, on Cloudflare

The Worker is in the worker folder of the repository and serves the pages in site. You need a Cloudflare account and Node.js 22 or later.

Try it on your computer

cd worker
npm install
cp .dev.vars.example .dev.vars
npm run dev

.dev.vars signs every visitor in as the Slack user ID in DEV_LOGIN, which only works on localhost. Open the address it prints and follow the setup steps on the dashboard.

Put it online

Connect the repository to Cloudflare. Nothing needs to be installed or signed in on your computer.

  1. In the Cloudflare dashboard, open Workers & Pages, then Create, then Import a repository. Choose your fork of the repository.
  2. Name the Worker helios. Set the root directory to worker, the build command to npm ci, and the deploy command to npm run deploy. Save and deploy. The first deploy creates the D1 database, its tables, and an R2 bucket that keeps every report for reviewers. It runs without the secrets, and the site says it is not set up yet.
  3. Create a Hack Club Auth app as in Set up sign-in below. Give it the openid, profile, and slack_id scopes, and https://<worker>.<your-subdomain>.workers.dev/auth/callback as its redirect URI. Cloudflare shows the address under the Worker's Settings, Domains & Routes.
  4. Under the Worker's Settings, Variables and Secrets, add these as secrets: SESSION_SECRET (any long random text), HCA_CLIENT_ID, HCA_CLIENT_SECRET, and ADMINS. Deploying again, which a push to the branch does, keeps them.

If the deploy fails:

  • The bucket needs R2 turned on for your Cloudflare account. You do that once, under R2 in the dashboard.
  • Permissions for D1 or R2: open the Worker's Settings, Builds, and give its API token D1 Edit and Workers R2 Storage Edit access.

Deploy from your computer instead

Run npx wrangler login in worker, then npm run deploy. Add the secrets in the dashboard or with npx wrangler secret put <NAME>.

Important

Deploy with npm run deploy, not npx wrangler deploy alone. npm run deploy applies the D1 migrations before the new code goes live. If you deploy by hand, run npx wrangler d1 migrations apply DB --remote first.

The order matters because the code reads columns that migrations add. For example, migration 0026_capped_days.sql adds prompt_days.uncapped_seconds, which every flush of a day's records writes. Code deployed before that migration is applied fails each flush until it is, and the records wait in the meantime.

Settings

SettingMeaning
SESSION_SECRETSigns sign-in cookies. Changing it signs everyone out.
HCA_CLIENT_ID, HCA_CLIENT_SECRETYour Hack Club Auth app.
ADMINSSlack user IDs of the superadmins, separated by commas. They add everyone else who reviews, in the review app.
GITHUB_TOKENOptional secret. Lets the hourly check ask GitHub which claimed commits exist, when GitHub dates them, and whose they are. Without it, commits are linked but not checked, and the review app says so.

  • Past one of them, the site answers 429 and helios keeps the records to send later.
  • The defaults are about ten times the heaviest honest use.
  • Records held back more than 5 minutes arrive late and aren't credited, so lower the limits with care.

For your own domain, add a custom domain to the Worker and use it in the redirect URI.

Cloudflare accepts uploads of up to 100 MB.

The review app

Reviewing has its own app at /review/, apart from the rest of the site. Reviewers get a Review link in the top bar.

Levels

What a reviewer can do depends on their level:

LevelWhoWhat they can do
SuperadminThe Slack IDs in ADMINS.Everything below, and add or remove neoadmins.
NeoadminAdded by a superadmin.Read every account: its computers, its projects, and a log of every report it sent. Each log entry shows what the report held and which days and projects changed, and links to the report itself, kept as it arrived. Add and remove reviewers. Ban people.
ReviewerAdded by a neoadmin or superadmin.Look a person up by Slack ID and read their total for each project, with each project's graphs, and their time through the Stats API. Nothing else of theirs.

Add someone or ban someone

Levels and bans are set on a person's account view, in its Access and Bans panels.

To add someone, look up their Slack ID in the app and choose a level in the Access panel of their account view.

A Slack ID that has never signed in opens a view with only those two panels. So a person can be added or banned before their first sign-in.

No one can add, remove, or ban someone at their own level or above. So a neoadmin can't touch another neoadmin.

The Reviewers and Bans pages list who holds each level and every ban, and link to each account view.

Project activity

Each person's page has a Project activity panel. For one project at a time, it draws:

  • engaged time and lines added and removed per day;
  • when in the week they work;
  • every work block's length against the share of it that was engaged.

It also checks the blocks for things to ask about:

  • time counted on two computers at once;
  • long blocks without breaks;
  • lines changed without a prompt;
  • very many lines per hour;
  • days over 14 hours.

A check that stands out is a reason to ask, not proof.

Bans

A ban has no length. It lasts until someone lifts it. It always has a reason, which only reviewers see.

While a ban holds:

  • The site takes nothing new from the person: no syncs, uploads, or cloud events.
  • helios sync, their dashboard, and their settings say plainly that they are banned until a reviewer lifts it, but not why.
  • They can still sign in and see what they had.
  • The review app marks them in red wherever they appear.
  • If they are a reviewer, they can't review.

Someone below the level of whoever issued a ban can't lift or replace it.

API keys

Any reviewer can make API keys, under API keys in the app, for a script or a bot.

  • A key acts as the person who made it, at the level they hold when it is used.
  • It stops working when they are removed or banned.
  • It is shown once, in a popup to copy it from. The site keeps only its hash.

Send it as a bearer token:

curl -H "Authorization: Bearer tdr_..." "https://your-site/api/review/person?slack=U012ABCDEF"

Stats API

Programs that credit hours, such as a You Ship, We Ship, read people's time here instead of taking submissions.

It is protected. Call it with a review key, made under API keys in the review app by someone with a place there. What the key sees depends on who made it:

  • A reviewer's key sees project names only.
  • A neoadmin's or superadmin's key also sees each project's key, such as github.com/you/site.
curl -H "Authorization: Bearer tdr_..." "https://your-site/api/review/stats?slack=U012ABCDEF&start=2026-01-01&end=2026-03-31"
ParameterMeaning
slackThe person's Slack ID. Neoadmins and superadmins may send id, the account number, instead.
start, endOptional. Days, such as 2026-01-31, on the person's own clock, both included. Without them, all of their time.
projectOptional. Project names, separated by commas, or keys for neoadmins and superadmins. Without it, every project.
flagsOptional. true reads the records behind the answer, at most 400 days of them, and lists flags for someone to look at.

The answer has these fields:

FieldWhat it holds
personslack_id, name, created_at, and deleted_at.
banreason and at, or null.
witnessed_seconds, unwitnessed_seconds, promptsThe person's three counts.
projectsThe projects, most witnessed time first. Each has name, key, the same three counts, first_day, and last_day.
daysEach date, with the same three counts.
flagsOnly when asked for. Each has kind and text.

Time on two projects at once counts once in the totals, and is split equally between those projects. So a person's projects add up to their total.

The answer is up to the moment.

The API only reports. Which time to credit, whether to count unwitnessed time, and how to treat a ban or a flag are the program's to decide.

Public API

Anyone with an account can read their own stats from a script, or let another site read them, for example to list your projects when you sign in there.

Make a read key under Settings, API. A read key:

  • starts with tdp_ and is shown once;
  • can only read. It can't upload, change, or delete anything;
  • doesn't sync. Likewise, your sync key doesn't work here;
  • reads nothing while your account is banned.
curl -H "Authorization: Bearer tdp_..." "https://your-site/api/public/v1/projects"
CallWhat it returns
GET /api/public/v1/mename, slack_id, created_at, engaged_seconds in the past year, and synced_at.
GET /api/public/v1/projectsprojects, most time first, each with name, repo (such as github.com/you/site, or null for a project that is only a folder), engaged_seconds, first_active, and last_active.
GET /api/public/v1/days?since=2026-01-01days: each date with its engaged_seconds. since is optional.
GET /api/public/v1/users/{handle}Anyone's public profile, with no key: handle, joined (YYYY-MM), engaged_seconds in the past year, days, projects (each with name, repo, and engaged_seconds), and other_projects (count and engaged_seconds). A private, banned, or unknown profile answers 404. Answers may be cached for a minute.
GET /api/public/v1/users/{handle}/badge.svgA badge of the profile's hours for a README, with no key. Add ?project= and a repository or project name the profile names for one project's hours. It shows only what the profile shows: a private, banned, or unknown profile, or a project the profile doesn't name, answers 404. Answers may be cached for 5 minutes.

Good to know:

  • Times are Unix milliseconds.
  • Answers are JSON. A refusal is plain text with its reason.
  • Any site may call the API from the browser, since it takes only the key and no cookies.
  • Folders on your computer are never shown, only repositories.

Sign in with helios

A site can get a read key without anyone pasting one.

1. Send the person to your helios site:

https://your-site/authorize?redirect_uri=https://example.com/callback&state=RANDOM&name=My+portfolio

They sign in if they need to, see the site's address and what it will read, and choose Allow.

2. Take the code they come back with. They come back to redirect_uri with code and your state, or with error=access_denied if they cancel. Check that state is the one you sent.

3. Trade the code for a key within 5 minutes, from your server or the browser:

curl -X POST https://your-site/api/public/v1/token \
  -d '{"code":"tdc_...","redirect_uri":"https://example.com/callback"}'

The answer is {"key": "tdp_...", "token_type": "Bearer", "name": ..., "slack_id": ...}. Use the key with the calls above.

The rules:

  • A code works once, for the redirect_uri it was made for. Trading it a second time also revokes the key it became.
  • redirect_uri must use https, except on localhost.
  • A site without a server should add PKCE: send code_challenge, the base64url SHA-256 of a random verifier, and send code_verifier with the code.
  • The key shows under the person's Settings, API, named after your site, where they can revoke it.
  • Each site keeps at most 5 keys per person. Signing in again after that revokes the oldest.
  • Banned accounts can't sign in.

Set up sign-in

  1. Open Developer Apps on auth.hackclub.com and create an app with the openid, profile, and slack_id scopes.
  2. Add https://your-site/auth/callback as its redirect URI.
  3. Copy the app's client ID and client secret into the Worker's secrets.
  4. Collect the Slack user ID of each superadmin for ADMINS: in Slack, open their profile, choose ⋮, then Copy member ID.

Privacy

Chat logs and prompt text never leave your computer.

What helios reads

helios reads timestamps, token counts, line counts, and working folders from your logs.

Prompt text is only scored in memory, to count recognized words. It is never stored or printed, and sync never uploads it.

What it sends to your website

In Amp's cloud, the plugin sends your website each prompt's time, thread, folder, repository, and word counts, without its text. Every other harness's hooks send the same kind of record.

What the website keeps

  • Records. The website keeps these records in R2 for good.
  • Reports. The website keeps each report your computers send, which holds those counts and times, so reviewers can read it. Deleting your account deletes them.
  • Your public profile. It shows your hours, your days, and the projects it names to anyone, unless you make it private.

See for yourself

To see exactly what leaves your computer, do either of these:

  • Run helios sync -dry-run. It prints the records the next sync would send, and sends nothing.
  • Pipe a hook payload into helios hook -check <tool>.

Troubleshooting

Start with helios doctor. It checks for the usual causes below and prints what to run for each problem it finds.

“No Claude Code, Codex, or Amp sessions found”

  • Run helios setup to see where helios looked.
  • If your logs live somewhere else, such as inside WSL on Windows, pass -claude-dir or -codex-dir.
  • If your last session was more than a week ago, try -since 30d.

“helios: command not found”

Open a new terminal so the PATH change applies.

On Windows, the PowerShell window you installed from already has it. Restart any other terminal that was open during the install.

“skipped N log files that could not be read”

Run helios -verbose to list them. Usually they are files a tool is still writing, and the rest of the report is unaffected.

“Your clock is N minutes ahead of (or behind) the site's”

The site expects each computer's clock to be close to its own. helios sync warns once the two are 2 minutes apart.

In your system's date and time settings, turn on setting the time automatically. Then sync again.

My hours look too low or too high

Compare ENGAGED with how long you think you worked, and please open an issue with the numbers.

Uninstall

helios uninstall

It asks once, then:

  1. Removes helios's hooks from Claude Code, Codex, Cursor, and Copilot, and its Amp and OpenCode plugins.
  2. Removes the line the installer added to your shell profile, or on Windows the folder it added to your Path. Your other settings and lines stay as they were.
  3. Asks whether to keep the journal folder, which holds this computer's account key and any records not sent yet.
  4. Deletes the binary. Windows can't delete a running program, so there it tells you to delete helios.exe once the window closes.

-yes answers every question. It deletes the journal folder unless you add -keep-data.

What stays behind

  • Your account on the site keeps what it has. Remove the computer under Settings, Computers.
  • Claude Code's longer history setting stays.
  • helios's .helios-backup copies of settings files stay.

Remove only the hooks

To remove the hooks and keep helios, run helios setup -remove-hooks.
