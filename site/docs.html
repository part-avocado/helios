helios docs

Everything you need to install helios, read your stats, and sync them to your site.

Quick start

Install helios. On macOS, Linux, or Git Bash on Windows:

curl -fsSL https://raw.githubusercontent.com/part-avocado/helios/main/install.sh | sh

On Windows, in PowerShell:

irm https://raw.githubusercontent.com/part-avocado/helios/main/install.ps1 | iex

The installer then runs helios setup, which lists the tools it found and asks before each change: to keep Claude Code transcripts past 30 days, and to add helios's hooks or plugin to Claude Code, Codex, Amp, OpenCode, Copilot, and Cursor. Saying yes to each is the recommended setup; see helios setup. Then use your tools as you normally do.

Just this computer

Run helios for your timeline and project totals, or helios dashboard for charts in your browser. You need no account, and nothing leaves your computer.

On the website

To see every computer's hours in one place:

  1. Open the dashboard and sign in with Hack Club. Your first sign-in creates your account.
  2. Run the command the dashboard shows, then type the code your terminal prints on the site.
  3. Do the same on each computer you code on. Each one syncs by itself from then on.

Install

macOS, Linux, and Git Bash on Windows

curl -fsSL https://raw.githubusercontent.com/part-avocado/helios/main/install.sh | sh

Windows (PowerShell)

irm https://raw.githubusercontent.com/part-avocado/helios/main/install.ps1 | iex

The installer downloads the right binary, checks it against the release's checksums.txt (it needs sha256sum, shasum, or openssl for that, and installs nothing without one), and installs it without admin rights to ~/.local/bin, or %LOCALAPPDATA%\Programs\helios on Windows. It adds that folder to your PATH, then runs helios setup. The first command writes the PATH change to your shell's profile, so open a new terminal before you run helios yourself. The PowerShell one also adds the folder to the window you installed from, so helios works there straight away; restart any other terminal that was already open.

Updating

To update later, run helios update, or run the install command again. helios update -check only says whether a newer version is out, and helios update v0.5.0 installs one version in particular, even an older one. helios update and the installer both run helios setup again with the new version, to bring hooks and plugins up to date.

Once a day, a background sync checks for a newer release, and helios prints one line when there is one. helios updates itself only if you run helios update -auto on: then that daily check installs each new release once it matches the release's checksums and runs as that version, keeps the one it replaced beside it with .old on the end, and says so for three days. Run helios setup after an update like this to bring hooks and plugins up to date. The checksums come from the same release as the binary, so auto-update trusts GitHub and helios's release workflow as much as the installer does. helios update -auto off stops it.

Installer options

These optional environment variables change what the installer does:

VariableEffect
HELIOS_VERSIONInstall a specific release, such as v0.1.0.
HELIOS_INSTALL_DIRInstall to another folder.
HELIOS_NO_MODIFY_PATHDon't edit your shell profile or PATH; print the line to add instead.
HELIOS_NO_SETUPDon't run helios setup afterwards.
HELIOS_CLOUDSet to 1 in a cloud environment, Codespace, or dev container: sets up Claude Code and every other tool found, without asking. Also set HELIOS_SERVER and HELIOS_KEY there; see Claude Code in the cloud.
HELIOS_BASE_URLDownload the binary and checksums.txt from this URL instead of the GitHub release, such as a mirror.

With Go 1.25 or later you can also run go install github.com/part-avocado/helios/cmd/helios@latest.

helios setup

helios setup shows every place helios looks for logs, how many sessions it found, and when the newest one is from. Then it offers to:

  • Keep Claude Code history. Claude Code deletes transcripts after 30 days by default. Setup offers to raise cleanupPeriodDays to 3650.
  • Add Claude Code hooks for real-time capture. See Claude Code.
  • Add Codex hooks. See Codex.
  • Add the Amp plugin. See Amp.
  • Add the OpenCode plugin. See OpenCode.
  • Add Copilot and Cursor hooks. See Copilot and Cursor.
  • Add Antigravity hooks. See Antigravity.

For cloud sessions of a repository, such as Claude Code on the web or Codex cloud, run helios setup -project in it instead. See Remote sessions.

To set up one tool only, name it: helios setup claude, codex, amp, opencode, antigravity, copilot, or cursor. You can name more than one. Setup offers the Amp plugin even on a computer where Amp isn't installed yet, so it is in place when Amp is.

Note

Setup never changes anything without a yes. It keeps your own hooks and settings, saves a backup the first time it edits a file, and is safe to run again. Pass -yes to accept everything without prompts.

The report

Run helios to see the last 7 days, or helios -since 30d for longer. The first table lists work blocks; the second totals each project. Add -l (or --live) to keep it on screen and update it as you work; press Ctrl-C to quit.

ColumnMeaning
ENGAGEDTime you were plausibly involved. This is the number that matters.
SPAN / SESSION TIMEWall-clock time from first to last activity, for comparison.
PROMPTSPrompts you sent that counted.
SKIPPEDPrompts that earned no time.
TOKENS IN/OUTTokens the model read (cached ones included) and wrote.
TOOLSWhich AI tools you used in that block.

A project is identified by its git remote, then its repository folder, then its working folder, so the same repo adds up across tools and clones. A folder in your home folder is written from it, as ~/code/app (and your home folder itself as home), so the key your site sees doesn't name your account on the computer. Projects that were keyed by their full folder before helios did this show up twice on your site: the old key holds the time from before, the new one the time since, and no time counts twice. Add -json to get the report as data.

The dashboard

The dashboard shows an activity heatmap, daily totals, projects, tools, and recent work blocks. There are two ways to open it.

The graphs are interactive. Hover a day, bar, or tool for the details. Click a day on the heatmap, or a bar, to list that day's work blocks (a week, on the yearly chart). Click a project in the table to see only that project; every number and chart follows it. Click again, or the chip at the top, to clear it.

On the website, with an account

The dashboard on the website adds up the hours from every computer you code on. Only you and your server's reviewers can see the dashboard; your public profile shows a summary to anyone.

  1. Open the dashboard and sign in with Hack Club. Your first sign-in creates your account.
  2. Run the command the dashboard shows, then type the code your terminal prints on the site. That connects this computer to your account; do the same on each computer you code on.
  3. Keep working. The page fills in as soon as the first sync arrives, and helios syncs again each time a reply finishes in Claude Code or Amp, or you stop one. Run helios sync to update it right away.

The Projects page lists every project you've worked on; open one to see that project on its own. A project's page also has its settings: Public, whether your public profile names it, and the GitHub repositories linked to it, which you can add or remove.

Settings has the rest:

PaneWhat it's for
SetupWhat to run to connect another computer, and your sync keys. A sync key only uploads stats: each computer gets its own, and cloud sessions (Claude Code in the cloud, Amp threads) get one named "Cloud sessions". Revoke one and only it stops working.
ComputersEach computer that syncs to you and when it last did. Remove one to drop its hours.
DataUpload a stats file from a computer that can't reach the website (make it with helios export -o stats.json, and upload it within 7 days), or download a copy of everything the site holds about you.
AccountYour name, Slack ID, and member-since date from Hack Club Auth, sign out, and deleting your account. Deleting removes every computer and all of your stats from the site.

You can sign out from the sidebar, or on a narrow window from the menu at the top right. A computer syncs to one account. To move it to another, remove it under Computers first.

On your computer, without an account

Run helios dashboard to open the same charts with live data from this computer, refreshed every 30 seconds. It runs on localhost only and refuses requests from other sites, so your stats never leave your computer.

Your public profile

Every account has a public profile at /@handle, which anyone can open without signing in. It shows your handle, the month you joined, your hours in the past year, a year of days, and your projects. It never shows your name, your Slack ID, or a folder on your computer. A project that is a repository on a public host, such as github.com/you/site, is public by default, named and linked to its repositories; any other project is only counted, as one of your other projects, until you make it public. Turn Public on or off on each project's page. Under Settings, Profile, you can change your handle or make the whole profile private. Settings, Profile also has a badge of your hours to paste into a README, linked to your profile. A private profile, like a banned or deleted account, answers "no such profile", so its address doesn't say that the account exists.

Each account starts with a neutral handle, such as u-3f9a0c12b4d1, never one made from your name. When you change it, the old address stops working.

Verification keys

Every sync and export carries a verification key: an Ed25519 signature, made by your account, over the report's numbers, the time it was made, and the time it expires. Change one minute of engaged time, the account, or a date, and the key no longer matches. The website refuses a report that:

  • has no key, or a key that doesn't match its contents;
  • is more than 7 days old, so an old or reused file can't stand in for current numbers;
  • claims to be made in the future, or contains activity after the time it was made.

Each computer's key is created the first time it syncs or exports and kept in helios's data folder as account.key. Settings lists your computers by the ID of that key, such as td-4283292a8f76.

Warning

Verification proves a file wasn't edited after helios export made it. Because the account key lives on your computer, a file alone can't prove the numbers are real. For hours that count, sync.

Tokens

Token counts come from the usage records Claude Code and Codex save with each response. A Claude Code response that's written several times, or copied into a resumed session, counts once. Codex counts are taken from the increase in its running totals. Amp counts come from the usage Amp hands the helios plugin when a turn ends, so they start with helios v0.6.0: Amp turns recorded before that show no tokens.

Claude Code

helios reads transcripts from $CLAUDE_CONFIG_DIR (which may list several folders), ~/.claude, and ~/.config/claude. It tells your prompts apart from tool results, compaction summaries, background notices, and subagent activity. Subagent transcripts are ignored: their time, tokens, and edits do not count.

With hooks installed, Claude Code runs helios hook claude-code when a session starts or ends, when you send a prompt, and when Claude finishes. Each run appends one line to a local journal: the time, session, folder, and the prompt's word counts and fingerprint, never its text. If Claude Code deletes a transcript, the journal still has that session.

Claude Code in the cloud, Codespaces, and remote machines

Which setup fits depends on whether the machine lasts.

A machine you keep, such as an SSH box

Install helios there and connect it like any computer. With no browser on it, run helios login -server https://your-site -no-open, which prints a code to type on the site from any other device. Or make a sync key under Settings on the site and run helios sync -server https://your-site -key tdk_…. The box keeps its own journal, is listed as a computer of its own, and syncs in the background.

Setting HELIOS_SERVER and HELIOS_KEY in the box's environment works too, with no login: hooks then send each event as it happens and sync in the background, just as after a login.

A machine that goes away: cloud sessions, Codespaces, dev containers

Transcripts and the journal in a cloud container disappear with it, so there helios sends each hook event straight to your site instead of keeping a journal. This is cloud mode. It is on when HELIOS_SERVER and HELIOS_KEY are both set and one of CLAUDE_CODE_REMOTE, CODESPACES, or HELIOS_CLOUD is 1 or true. Claude Code on the web sets the first and GitHub Codespaces the second by themselves.

  1. On the site, make a key under Settings.
  2. Add two secrets to the environment: HELIOS_SERVER (your site) and HELIOS_KEY (the key). For Codespaces, add them as Codespaces secrets of your account or the repository. Also set HELIOS_CLOUD=1 unless the environment sets CLAUDE_CODE_REMOTE or CODESPACES itself.
  3. Add this to the environment's setup script, or for a Codespace or dev container, to postCreateCommand in devcontainer.json:
curl -fsSL https://raw.githubusercontent.com/part-avocado/helios/main/install.sh | HELIOS_CLOUD=1 sh

It installs helios, creates ~/.claude if no Claude Code folder exists, and adds the hooks of every tool it finds without asking. helios doctor says whether cloud mode is on, and which secret is missing when it is not.

Or commit the hooks to the repository

If you can't edit the environment's setup script, run this once in the repository, on your own computer, and commit the file it writes:

helios setup claude -project

It adds hooks to the repository's .claude/settings.json, keeping whatever is there. In a session where HELIOS_KEY is set, the session's start installs helios if it is missing, and each prompt and reply runs helios hook claude-code -project, found on PATH or in ~/.local/bin. Where HELIOS_KEY is not set, they do nothing: nothing is installed or recorded for teammates who don't use helios. They also do nothing where your own Claude Code settings already have helios's hooks, as on your own computer or a machine the setup script set up, so each event is recorded once. You still add the two secrets to the environment. If the repository's hooks don't end in -project, an older helios added them: run helios setup claude -project again and commit the change, since those don't check for your own hooks. helios setup claude -project -remove-hooks takes them out again.

What cloud mode sends

Each event goes to your site as it happens, with what a journal line holds: the time, tool, session, and a prompt's word counts and fingerprint, never its text. Because the site can't look the folder up later, the event also carries the repository, named from its origin remote without any sign-in the remote holds, and the folder's path inside the container, such as /home/user/repo. A reply's end carries the tokens and lines of that turn, read from the transcript, and your commits in the repository since the last one. No sync runs there, and no account key is made.

Cloud sessions all count as one computer, called "cloud", however many containers ran them, so a new container never adds a computer to your list. That computer has no clock correction and no time zone of its own: its records are used at the times the container gave them, and its days are counted at the UTC offset your own computers pinned for your account. Subagent activity is not counted there either.

Codex

helios reads rollouts from $CODEX_HOME or ~/.codex, in both sessions and archived_sessions, including compressed .jsonl.zst files. It handles both the older and the current (0.147 and later) log formats. Subagent and reviewer sessions never count as your prompts.

helios setup also adds hooks to ~/.codex/hooks.json, so each prompt and turn end reaches your site as it happens, and a notify line to ~/.codex/config.toml, which syncs when a turn ends. Codex skips new hooks until you trust them: open Codex, run /hooks, and trust helios's. The notify line needs no trust step, so Codex syncs on its own either way. If your config.toml already has a notify program, helios leaves it alone.

Remote machines and the cloud

On an SSH box, Codespace, or cloud container, set helios up as for Claude Code. Two things differ for Codex. Its hooks still need the trust step, which a setup script can't do: run /hooks once in each new container, or they are skipped. And until then only notify runs, which reports turn ends and no prompts, so in cloud mode, where there is no sync to read the rollouts later, a container whose hooks were never trusted earns no time.

Amp

Amp keeps threads on its servers, so helios setup (or helios setup amp for Amp alone) offers to write a plugin to ~/.config/amp/plugins/helios.ts. It records when a thread starts, when you send a prompt, and when Amp finishes, in the same journal as the Claude Code hooks. New Amp threads load it automatically; in open ones, run plugins: reload.

Threads in Amp's cloud

Threads you start in the Amp app or on ampcode.com run in Amp's cloud, not on your computer, so that plugin can't see them. A second plugin, helios-cloud.ts, counts them. It goes in your personal Amp plugins, which Amp loads in every cloud thread.

  1. On your helios site, open Settings, Setup, and choose Amp under “Check your tools”.
  2. Paste the prompt shown there into any Amp thread. Amp adds the plugin and two values to its Secrets & Env Vars settings: HELIOS_SERVER, your site's address, and HELIOS_KEY, a sync key. Make it with Make a key for Amp under the prompt; it shows once, and is listed under your sync keys as "Cloud sessions". Amp asks you for the key in a private dialog, so it stays out of the thread.

In a cloud thread, the plugin downloads helios, checks it against the release's checksum, and runs it when you send a prompt and when Amp finishes. Each run sends your site one line: the time, thread, folder, repository, and the prompt's word counts and fingerprint, never its text. When Amp finishes, the line also holds the tokens the turn used and the lines its file edits added and removed, never the code. Your site keeps these lines for a year. At the end of each turn helios also sends your commits in the thread's repository, as helios sync does on a computer, so they show in the review app's graphs and can be checked against GitHub.

No computer of yours is needed. When Amp finishes a turn or you stop it, the helios in that thread reads all of your cloud lines back from your site, counts them with the same rules as everything else, and syncs the result. Threads that ran side by side are counted together, so their overlap counts once. Your cloud threads show up as one entry under Settings, Computers, named “Cloud sessions”.

Note

Cloud time reaches your dashboard when Amp finishes a turn or you stop it. Its days are split at midnight UTC, because a cloud thread doesn't know your time zone. The Mac app's threads can also run on your Mac instead of the cloud: open the app's App Settings, Runner, turn it on, and pick “This Mac” when you start a thread. Those are recorded by the first plugin.

Set up with a prompt

The dashboard's setup steps include a prompt to paste into Amp or Claude Code, with your server already filled in. The agent installs helios, runs helios setup -yes to add the hooks and the plugin without stopping to ask, runs helios login and shows you the code to type on the site, and shows you the result. -yes is the part an agent can't do on its own, since setup otherwise asks before changing any settings. The prompt holds no key, so nothing secret ends up in that thread.

Copilot and Cursor

helios setup writes ~/.copilot/hooks/helios.json for GitHub Copilot CLI and VS Code's Copilot agent, and adds helios's hooks to ~/.cursor/hooks.json for Cursor, keeping any hooks of your own. Restart Cursor to load them. Neither keeps transcripts helios can read, so their time comes from the hooks alone, and only reaches your site when one is set up with helios sync.

Copilot CLI's hooks name no session, so helios names one after the folder it runs in: a hash of its path, never the path itself.

Remote machines and the cloud

On an SSH box, Codespace, or cloud container, set helios up as for Claude Code: with HELIOS_CLOUD=1 the installer sets up Copilot and Cursor too, where their ~/.copilot or ~/.cursor folder exists. If Copilot has not made its folder yet, run helios setup -yes copilot, which makes it. Their hooks then send each event straight to your site.

OpenCode

helios setup (or helios setup opencode) writes a plugin to ~/.config/opencode/plugins/helios.ts, or the plugins folder of $OPENCODE_CONFIG_DIR when that is set. OpenCode 1 and 2 both load it. It runs helios hook opencode when you send a prompt and when a turn ends, finished, failed, or stopped, recording the time and folder, never the prompt text. Prompts in a subagent's session come from the agent, so they aren't counted as yours. OpenCode keeps its history in a database helios doesn't read, so time before the plugin was added doesn't count.

Antigravity

helios setup (or helios setup antigravity) offers to add a helios group to Antigravity's global hooks file, ~/.gemini/config/hooks.json. The App, the CLI, and the IDE all read it. Your other hook groups are kept.

The group runs helios hook antigravity on three events:

EventRecorded as
SessionStartthe session starting
PreInvocation, on an execution's first model callyour prompt, scored for effort and repeats, then thrown away
Stopthe turn ending

Antigravity runs PreInvocation before every model call. Only the first call of an execution follows a prompt of yours, so helios skips the rest. Antigravity's hooks report no tokens, so its turns show no token counts.

Each hook prints {}, which is what Antigravity needs from a hook that changes nothing. To check that it loaded them, open the agent side panel, then Customizations, then Hooks. In the CLI, run /hooks.

helios setup -remove-hooks antigravity takes the group out again. For Antigravity on a remote machine, see Remote sessions.

Remote sessions

Some agents work on a machine that goes away: Claude Code on the web, Codex cloud tasks, a Codespace, or OpenCode or Antigravity on a remote VM. There helios runs in cloud mode, which Claude Code in the cloud describes. Each hook event goes straight to your site, and every cloud machine counts as one computer, called "cloud". Cloud mode is on when HELIOS_SERVER and HELIOS_KEY are set with HELIOS_CLOUD=1, CLAUDE_CODE_REMOTE=true (Claude Code on the web sets it), or CODESPACES=true.

A cloud machine starts from your repository and has no helios of its own. So commit hooks that install it:

helios setup -project            # Claude Code, Codex, Antigravity, and OpenCode
helios setup codex -project      # or only the tools you name
FileFor
.claude/settings.jsonClaude Code on the web
.codex/hooks.jsonCodex cloud
.agents/hooks.jsonAntigravity on a remote machine
.opencode/plugins/helios-project.tsOpenCode on a server

Your own settings in those files are kept. Each hook does nothing unless HELIOS_KEY is set, so nothing changes for a teammate who doesn't use helios. At a session's start it installs helios if it is missing, using the installer, which checks the release's checksums. The Codex, Antigravity, and OpenCode hooks record only in cloud mode: on your own computers, the hooks helios setup adds there record the session. Claude Code's stand down where your own settings already run helios's hook.

Set up an environment

  1. Run helios setup -project in the repository, then commit and push.
  2. Under Settings, Setup, on your site, make a sync key named after the environment.
  3. In the environment's settings, set HELIOS_SERVER to your site and HELIOS_KEY to that key. Outside Claude Code on the web and Codespaces, also set HELIOS_CLOUD=1.
  4. Let the environment reach github.com, raw.githubusercontent.com, and objects.githubusercontent.com, to install helios, and your site. For Claude Code on the web, use Limited network access and add your site under Allowed domains.

Warning

Anyone who can use the environment can read its variables. A sync key can only upload stats, and you can revoke it under Settings at any time.

WhereWhat to know
Claude Code on the webRuns a repository's hooks in a session with one repository.
Codex cloudCodex runs a repository's hooks once they are trusted. Check your dashboard after the first task, since a cloud task may not run them.
OpenCode on a serverThe plugin runs in the opencode serve process. Set the variables where it starts.
Antigravity, remoteThe workspace's .agents/hooks.json runs on the machine the agent works on.
Amp's cloudHas its own plugin: see Amp cloud threads.

A remote machine you keep can instead run the installer and helios login, like any computer. helios setup -project -remove-hooks takes the hooks out again.

Connectors

Chat apps have no hooks, but they can add a connector: a remote MCP server. Your site is one, at /mcp. Add it to Claude on the web (claude.ai), the Claude desktop and mobile apps, ChatGPT, or any app that takes a remote MCP server with OAuth, and its chats add to your hours.

Add it

In Claude, open Settings, then Connectors, choose Add custom connector, and give it your site's address followed by /mcp, such as https://helios.example/mcp. Other apps ask for the same address. The app sends you to your site, which shows what it will do. Choose Allow.

Your site makes the app a sync key named after it, such as "Claude connector". To disconnect the app, revoke that key under Settings, Setup.

What it records

The connector gives the model two tools:

ToolWhat it does
helios_logThe model calls it with start when it begins a reply and end when it finishes. Each call is one record, a prompt or a turn end, as a harness's hooks send.
helios_statsReads your hours, per day and per project, to answer questions such as "how much did I work this week?"

The site stamps each record with the time it arrives, so a chat's time is witnessed like any other, and it is credited by the same rules as any other tool's. A record carries the conversation as a digest of the name the model gives it, the word count of your message, and the repository if you name one. It never carries your message or the reply.

A chat counts under the app's own name, such as claude-ai or chatgpt, so reviewers can tell chat time from time in coding tools. Chats name no project unless the model passes a repository, such as github.com/owner/name, so they show as the app's chats.

Note

The model decides when to call the tools, so a chat in which it doesn't adds nothing. If yours skips them, ask it to log the conversation with helios.

Add your own harness

Any tool can report to helios. Run helios hook <tool>, where the tool name is lowercase letters, digits, and dashes, with one JSON object on stdin:

{"session_id": "abc123", "cwd": "/home/me/project", "hook_event_name": "prompt", "prompt": "add a login page"}
FieldMeaning
session_idRequired. One conversation or thread.
hook_event_nameRequired, or pass -event: prompt, turn_end, session_start, session_end, or edit.
cwdThe folder, which names the project by its git remote. Only the project key leaves the computer.
promptFor prompt: scored for effort and repeats on the computer, then thrown away. Its text is never stored or sent.
tokens_in, tokens_out, lines_added, lines_removedOptional, on turn_end or edit.

helios always exits 0 and prints nothing on stdout for a tool of your own, so it never gets in the tool's way. A built-in harness gets the one reply it needs there, such as Cursor's {"continue":true}, and if an event can't be written, the reason goes to stderr. It writes the event to the local journal, and, once the computer is connected, sends it to your site as it happens. helios hook -check <tool> prints the record a payload would make and writes nothing, for testing an adapter.

For a tool with a hooks file in Claude Code's shape, point its prompt and stop hooks at helios hook mytool. For a tool with plugins, run the same command from the plugin, as helios's own Amp plugin does with helios hook amp.

Lines of code

When a computer syncs, helios also sends your site one record per commit of yours in each project with a git remote: its SHA, author time, and lines added and removed, never its message or code. Commits earn no time. Your profile links a public repository's latest commits, and once an hour the site asks GitHub which of them exist, so a reviewer can tell a claimed commit GitHub doesn't have. For each commit GitHub has, the review app also shows the GitHub account it is linked to, and marks one whose claimed time differs from GitHub's author date: the SHA pins that date, so a difference means the time was changed after the commit was made. A private repository's commits are shown as not checked. The check needs a GITHUB_TOKEN secret on the Worker; without one, the review app says so.

For each project the report shows the lines agents changed (AGENT LINES), how many of the added lines later turned up in your commits (KEPT), and the lines your own commits added (COMMITTED). The code itself is not kept.

Sync

helios sync sends your account records: one per prompt and turn end, with its time, word counts, tokens, and lines, never its text. The first sync sends the past year; later ones send only what changed. The first time, connect the computer:

helios login -server https://your-site

It prints a code such as BCDF-GHJK and opens the site's connect page; sign in, type the code, and check that the computer ID it shows matches the one in your terminal. helios then saves a sync key of this computer's own and syncs. Each computer gets its own key, listed under Settings, Setup, by its computer ID, so you can revoke one without touching the rest. A code lasts 10 minutes and works once. It has to be typed rather than followed from a link, so nobody can send you a link that connects their computer to your account. Never type a code someone sent you: the page says when and from where each code was asked for, and allowing one gives that computer a sync key to your account. On a computer with no browser, make a sync key for it under Settings, Setup, and run helios sync -server https://your-site -key tdk_… there.

helios remembers the server and the key, so later it's just helios sync, and hooks sync in the background when a reply finishes or you stop one. Amp reports a stopped reply at once; Claude Code runs no hook then, so that sync happens at your next prompt or when the session closes. Codex syncs through its notify program when a turn ends. The key only sends records; it can't read or change your account or settings. If the server answers that it needs your sync key, run helios login again.

Programs that pay or credit hours read your time through the Stats API and decide what counts; helios itself credits nothing.

Your stats on the website are visible to you and to reviewers, apart from what your public profile shows: a reviewer sees, for each project, your total and a timeline of your work blocks (when each started and ended, with its prompts, tokens, and lines changed), and neoadmins and superadmins see everything you synced. Deleting your account, under Settings, removes them; admins keep your Slack ID and a record of what your computers reported, without project names. To host the site, see Running a server.

Running a server

The site is one Cloudflare Worker with a D1 database for summaries, an R2 bucket for every report and per-prompt record, and a Durable Object per account that takes records as they arrive and pushes them to open dashboards.

The website, on Cloudflare

The Worker is in the worker folder of the repository and serves the pages in site. You need a Cloudflare account and Node.js 22 or later.

To try it on your computer first:

cd worker
npm install
cp .dev.vars.example .dev.vars
npm run dev

.dev.vars signs every visitor in as the Slack user ID in DEV_LOGIN, which only works on localhost. Open the address it prints and follow the setup steps on the dashboard.

To put it online, connect the repository to Cloudflare. Nothing needs to be installed or signed in on your computer.

  1. In the Cloudflare dashboard, open Workers & Pages, then Create, then Import a repository. Choose your fork of the repository.
  2. Name the Worker helios, set the root directory to worker, the build command to npm ci, and the deploy command to npm run deploy. Save and deploy. The first deploy creates the D1 database, its tables, and an R2 bucket that keeps every report for reviewers. It runs without the secrets, and the site says it is not set up yet.
  3. Create a Hack Club Auth app as in Set up sign-in below, with the openid, profile, and slack_id scopes and https://<worker>.<your-subdomain>.workers.dev/auth/callback as its redirect URI. Cloudflare shows the address under the Worker's Settings, Domains & Routes.
  4. Under the Worker's Settings, Variables and Secrets, add these as secrets: SESSION_SECRET (any long random text), HCA_CLIENT_ID, HCA_CLIENT_SECRET, and ADMINS. Deploying again, which a push to the branch does, keeps them.

The bucket needs R2 turned on for your Cloudflare account, which you do once under R2 in the dashboard. If the build fails on permissions for D1 or R2, open the Worker's Settings, Builds, and give its API token D1 Edit and Workers R2 Storage Edit access.

To deploy from your computer instead, run npx wrangler login in worker, then npm run deploy, and add the secrets in the dashboard or with npx wrangler secret put <NAME>.

Deploy with npm run deploy, not npx wrangler deploy alone: it applies the D1 migrations before the new code goes live. The code reads columns that migrations add, so the order matters. Migration 0026_capped_days.sql adds prompt_days.uncapped_seconds, which every flush of a day's records writes; code deployed before it is applied fails each flush until it is, and the records wait in the meantime. If you deploy by hand, run npx wrangler d1 migrations apply DB --remote first.

SettingMeaning

Their records wait on their computers and arrive late, so late that their time isn't credited, so raise it only for a fix that needs it. Empty answers every version.
UPLOAD_BURST, RECENT_RECORDS_PER_DAY, OLD_RECORDS_PER_DAYWhat one account may send: 1,000 uploads at once, which come back one a second; 30,000 records a day dated in the last two days; and 100,000 older ones a day, for a first sync of a year (set OLD_RECORDS_PER_DAY higher if you need to import more). Past one, the site answers 429 and helios keeps the records to send later. The defaults are about ten times the heaviest honest use. Records held back more than 5 minutes arrive late and aren't credited, so lower them with care.

To change a secret later, edit it in the dashboard. For your own domain, add a custom domain to the Worker and use it in the redirect URI. Cloudflare accepts uploads of up to 100 MB.

The review app

Reviewing has its own app at /review/, apart from the rest of the site. Reviewers get a Review link in the top bar. What a reviewer can do depends on their level:

LevelWhoWhat they can do
SuperadminThe Slack IDs in ADMINS.Everything below, and add or remove neoadmins.
NeoadminAdded by a superadmin.Read every account: its computers, its projects, and a log of every report it sent. Each log entry shows what the report held and which days and projects changed, and links to the report itself, kept as it arrived. Add and remove reviewers. Ban people.
ReviewerAdded by a neoadmin or superadmin.Look a person up by Slack ID and read their total for each project, with each project's graphs, and their time through the Stats API. Nothing else of theirs.

To add someone, look up their Slack ID in the app and choose a level in the Access panel of their account view. They can be added before they first sign in. No one can add, remove, or ban someone at their own level or above, so a neoadmin can't touch another neoadmin.

Each person's page has a Project activity panel. For one project at a time it draws engaged time and lines added and removed per day, when in the week they work, and every work block's length against the share of it that was engaged. It also checks the blocks for what to ask about: time counted on two computers at once, long blocks without breaks, lines changed without a prompt, very many lines per hour, and days over 14 hours. A check that stands out is a reason to ask, not proof.

Levels and bans are set on a person's account view, in its Access and Bans panels. A Slack ID that has never signed in opens a view with only those two, so a person can be added or banned before their first sign-in. The Reviewers and Bans pages list who holds each level and every ban, and link to each account view.

A ban has no length: it lasts until someone lifts it, and always has a reason, which only reviewers see. While it holds, the site takes nothing new from the person: no syncs, uploads, or cloud events. helios sync, their dashboard, and their settings say plainly that they are banned until a reviewer lifts it, but not why. They can still sign in and see what they had. The review app marks a banned person in red wherever they appear. A banned reviewer can't review. Someone below the level of whoever issued a ban can't lift or replace it.

Any reviewer can make API keys, under API keys in the app, for a script or a bot. A key acts as the person who made it, at the level they hold when it is used, and stops working when they are removed or banned. The key is shown once, in a popup to copy it from; the site keeps only its hash. Send it as a bearer token:

curl -H "Authorization: Bearer tdr_..." "https://your-site/api/review/person?slack=U012ABCDEF"

Stats API

Programs that credit hours, such as a You Ship, We Ship, read people's time here instead of taking submissions. It is protected: call it with a review key, made under API keys in the review app by someone with a place there. A reviewer's key sees project names only; a neoadmin's or superadmin's also sees each project's key, such as github.com/you/site.

curl -H "Authorization: Bearer tdr_..." "https://your-site/api/review/stats?slack=U012ABCDEF&start=2026-01-01&end=2026-03-31"
ParameterMeaning
slackThe person's Slack ID. Neoadmins and superadmins may send id, the account number, instead.
start, endOptional. Days, such as 2026-01-31, on the person's own clock, both included. Without them, all of their time.
projectOptional. Project names, separated by commas, or keys for neoadmins and superadmins. Without it, every project.
flagsOptional. true reads the records behind the answer, at most 400 days of them, and lists flags for someone to look at.

The answer has person (slack_id, name, created_at, deleted_at), ban (reason and at, or null), witnessed_seconds, unwitnessed_seconds, and prompts; projects, most witnessed time first, each with name, key, the same three counts, first_day, and last_day; days, each date with the same three counts; and flags when asked, each with kind and text. Time on two projects at once counts once in the totals, and is split equally between those projects, so a person's projects add up to their total. The answer is up to the moment. Which time to credit, whether to count unwitnessed time, and how to treat a ban or a flag are the program's to decide.

Public API

Anyone with an account can read their own stats from a script, or let another site read them, for example to list your projects when you sign in there. Make a read key under Settings, API. It starts with tdp_, is shown once, and can only read: it can't upload, change, or delete anything. Your sync key doesn't work here, and a read key doesn't sync. While your account is banned, your read keys read nothing.

curl -H "Authorization: Bearer tdp_..." "https://your-site/api/public/v1/projects"
CallWhat it returns
GET /api/public/v1/mename, slack_id, created_at, engaged_seconds in the past year, and synced_at.
GET /api/public/v1/projectsprojects, most time first, each with name, repo (such as github.com/you/site, or null for a project that is only a folder), engaged_seconds, first_active, and last_active.
GET /api/public/v1/days?since=2026-01-01days: each date with its engaged_seconds. since is optional.
GET /api/public/v1/users/{handle}Anyone's public profile, with no key: handle, joined (YYYY-MM), engaged_seconds in the past year, days, projects (each with name, repo, and engaged_seconds), and other_projects (count and engaged_seconds). A private, banned, or unknown profile answers 404. Answers may be cached for a minute.
GET /api/public/v1/users/{handle}/badge.svgA badge of the profile's hours for a README, with no key. Add ?project= and a repository or project name the profile names for one project's hours. It shows only what the profile shows: a private, banned, or unknown profile, or a project the profile doesn't name, answers 404. Answers may be cached for 5 minutes.

Times are Unix milliseconds. Answers are JSON; a refusal is plain text with its reason. Any site may call the API from the browser, since it takes only the key and no cookies. Folders on your computer are never shown, only repositories.

Sign in with helios

A site can get a read key without anyone pasting one. Send the person to:

https://your-site/authorize?redirect_uri=https://example.com/callback&state=RANDOM&name=My+portfolio

They sign in if they need to, see the site's address and what it will read, and choose Allow. They come back to redirect_uri with code and your state, or with error=access_denied if they cancel. Check that state is the one you sent, then trade the code within 5 minutes, from your server or the browser:

curl -X POST https://your-site/api/public/v1/token \
  -d '{"code":"tdc_...","redirect_uri":"https://example.com/callback"}'

The answer is {"key": "tdp_...", "token_type": "Bearer", "name": ..., "slack_id": ...}. Use the key with the calls above. A code works once, for the redirect_uri it was made for; trading it a second time also revokes the key it became. redirect_uri must use https, except on localhost. A site without a server should add PKCE: send code_challenge, the base64url SHA-256 of a random verifier, and send code_verifier with the code. The key shows under the person's Settings, API, named after your site, where they can revoke it. Each site keeps at most 5 keys per person; signing in again after that revokes the oldest. Banned accounts can't sign in.

Set up sign-in

  1. Open Developer Apps on auth.hackclub.com and create an app with the openid, profile, and slack_id scopes.
  2. Add https://your-site/auth/callback as its redirect URI.
  3. Copy the app's client ID and client secret into the Worker's secrets.
  4. Collect the Slack user ID of each superadmin for ADMINS: in Slack, open their profile, choose ⋮, then Copy member ID.

Hosting cost

node worker/scripts/cost-model.ts [prompts per hour] prints the monthly bill from named inputs, with Cloudflare's prices of 2026-11-22. For 15,488 people logging 109,759 engaged hours a month at 20 prompts an hour, it comes to about $10 a month after a year and $13 after three ($27 and $35 at 60 prompts an hour), against a $500 limit. Every record, every report, and the account log's older rows are kept in R2 for good; D1 keeps each person's newest few hundred log rows and the day totals, which pass D1's 10 GB limit in about year 6 unless old days are folded into months. The inputs are assumptions until measured against a real deploy.

Privacy

helios reads timestamps, token counts, line counts, and working folders from your logs. Prompt text is only scored in memory to count recognized words; it is never stored or printed, and sync never uploads it. In Amp's cloud, the plugin sends your website each prompt's time, thread, folder, repository, and word counts, without its text, and every other harness's hooks send the same kind of record. The website keeps these records in R2 for good. The website keeps each report your computers send, which holds those counts and times, so reviewers can read it; deleting your account deletes them. Your public profile shows your hours, your days, and the projects it names to anyone, unless you make it private. Chat logs and prompt text never leave your computer.

To see exactly what leaves your computer, run helios sync -dry-run, which prints the records the next sync would send and sends nothing, or pipe a hook payload into helios hook -check <tool>.

Troubleshooting

Start with helios doctor. It checks the usual causes below and prints what to run for each one it finds.

“No Claude Code, Codex, or Amp sessions found”

Run helios setup to see where helios looked. If your logs live elsewhere, such as inside WSL on Windows, pass -claude-dir or -codex-dir. Try -since 30d if your last session was more than a week ago.

“helios: command not found”

Open a new terminal so the PATH change applies. On Windows, the PowerShell window you installed from already has it; restart any other terminal that was open during install.

“skipped N log files that could not be read”

Run helios -verbose to list them. Usually they are files a tool is still writing, and the rest of the report is unaffected.

“Your clock is N minutes ahead of (or behind) the site's”

The site expects each computer's clock to be close to its own, and helios sync warns from 2 minutes off. Turn on setting the time automatically in your system's date and time settings, then sync again.

My hours look too low or too high

Compare ENGAGED with how long you think you worked, and please open an issue with the numbers.

Uninstall

helios uninstall

It asks once, then removes helios's hooks from Claude Code, Codex, Cursor, and Copilot, its Amp and OpenCode plugins, and the line the installer added to your shell profile (on Windows, the folder it added to your Path), leaving your other settings and lines as they were. It asks whether to keep the journal folder, which holds this computer's account key and any records not sent yet, and deletes the binary last. Windows can't delete a running program, so there it tells you to delete helios.exe once the window closes. -yes answers every question, deleting the journal folder unless you add -keep-data.

Your account on the site keeps what it has; remove the computer under Settings, Computers. Claude Code's longer history setting and helios's .helios-backup copies of settings files stay. To remove only the hooks and keep helios, run helios setup -remove-hooks.
