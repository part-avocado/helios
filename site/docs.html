teardrop docs

Everything you need to install teardrop, read your stats, and submit your hours for review.

Quick start

  1. Install teardrop with the command for your OS below.
  2. Answer the questions teardrop setup asks. Saying yes to each is the recommended setup.
  3. Use Claude Code, Codex, or Amp as you normally do.
  4. Run teardrop for your timeline, or teardrop dashboard for charts.
  5. To see every computer's hours in one place, sign in to the dashboard and connect each one.

Install

macOS, Linux, and Git Bash on Windows

curl -fsSL https://raw.githubusercontent.com/part-avocado/teardrop/main/install.sh | sh

Windows (PowerShell)

irm https://raw.githubusercontent.com/part-avocado/teardrop/main/install.ps1 | iex

The installer downloads the right binary, checks it against the release's checksums.txt, and installs it without admin rights to ~/.local/bin, or %LOCALAPPDATA%\Programs\teardrop on Windows. It adds that folder to your PATH, then runs teardrop setup. Open a new terminal afterwards so the PATH change applies.

Run the same command again to update. These optional environment variables change what it does:

VariableEffect
TEARDROP_VERSIONInstall a specific release, such as v0.1.0.
TEARDROP_INSTALL_DIRInstall to another folder.
TEARDROP_NO_MODIFY_PATHDon't edit your shell profile or PATH; print the line to add instead.
TEARDROP_NO_SETUPDon't run teardrop setup afterwards.

With Go 1.25 or later you can also run go install github.com/part-avocado/teardrop/cmd/teardrop@latest.

teardrop setup

teardrop setup shows every place teardrop looks for logs, how many sessions it found, and when the newest one is from. Then it offers to:

  • Keep Claude Code history. Claude Code deletes transcripts after 30 days by default. Setup offers to raise cleanupPeriodDays to 3650.
  • Add Claude Code hooks for real-time capture. See Claude Code.
  • Add the Amp plugin. See Amp.

To set up one tool only, name it: teardrop setup amp, teardrop setup claude, or teardrop setup codex. teardrop setup amp adds the plugin even on a computer where Amp isn't installed yet.

Note

Setup never changes anything without a yes. It keeps your own hooks and settings, saves a backup the first time it edits a file, and is safe to run again. Pass -yes to accept everything without prompts.

The report

Run teardrop to see the last 7 days, or teardrop -since 30d for longer. The first table lists work blocks; the second totals each project. Add -l (or --live) to keep it on screen and update it as you work; press Ctrl-C to quit.

ColumnMeaning
ENGAGEDTime you were plausibly involved. This is the number that matters.
SPAN / SESSION TIMEWall-clock time from first to last activity, for comparison.
PROMPTSPrompts you sent that counted.
SKIPPEDPrompts that earned no time.
TOKENS IN/OUTTokens the model read (cached ones included) and wrote.
TOOLSWhich AI tools you used in that block.

A project is identified by its git remote, then its repository folder, then its working folder, so the same repo adds up across tools and clones. Add -json to get the report as data.

The dashboard

The dashboard shows an activity heatmap, daily totals, projects, tools, and recent work blocks. There are two ways to open it.

The graphs are interactive. Hover a day, bar, or tool for the details. Click a day on the heatmap, or a bar, to list that day's work blocks (a week, on the yearly chart). Click a project in the table to see only that project; every number and chart follows it. Click again, or the chip at the top, to clear it.

On the website, with an account

The dashboard on the website adds up the hours from every computer you code on. Only you and your server's admins can see them.

  1. Open the dashboard and sign in with Hack Club. Your first sign-in creates your account.
  2. Run the two commands it shows: one installs teardrop, the other connects that computer to your account.
  3. Keep working. The page fills in as soon as the first sync arrives, and teardrop syncs again every 15 minutes while you use Claude Code or Amp. Run teardrop sync to update it right away.

Settings has the rest:

PaneWhat it's for
SetupThe commands to connect another computer, and a button to make a new sync key if yours gets out.
ComputersEach computer that syncs to you and when it last did. Remove one to drop its hours.
DataUpload a stats file from a computer that can't reach the website (make it with teardrop export -o stats.json, and upload it within 7 days), or download a copy of everything the site holds about you.
AccountYour name, Slack ID, and member-since date from Hack Club Auth, sign out, and deleting your account. Deleting removes every computer and all of your stats from the site.

You can sign out from the menu at the top right of any page. A computer syncs to one account. To move it to another, remove it under Computers first.

On your computer, without an account

Run teardrop dashboard to open the same charts with live data from this computer, refreshed every 30 seconds. It runs on localhost only and refuses requests from other sites, so your stats never leave your computer.

Verification keys

Every sync and export carries a verification key: an Ed25519 signature, made by your account, over the report's numbers, the time it was made, and the time it expires. Change one minute of engaged time, the account, or a date, and the key no longer matches. The website refuses a report that:

  • has no key, or a key that doesn't match its contents;
  • is more than 7 days old, so an old or reused file can't stand in for current numbers;
  • claims to be made in the future, or contains activity after the time it was made.

Each computer's key is created the first time it syncs or exports and kept in teardrop's data folder as account.key. Settings lists your computers by the ID of that key, such as td-4283292a8f76.

Warning

Verification proves a file wasn't edited after teardrop export made it. Because the account key lives on your computer, a file alone can't prove the numbers are real. For hours that count, use teardrop submit: the server checks the hours against the chat logs behind them.

What counts

teardrop counts the time you spend working with your AI tools: writing prompts, reading replies, and steering the agent. An agent left running on its own doesn't earn time, and parallel sessions on one project count once. Prompts that don't reflect real work aren't counted; they're listed as SKIPPED.

Important

Testing doesn't count. Time spent testing your build outside the agent chat, such as clicking through the app or writing up feedback before you send it, isn't counted by teardrop. Record it with Lapse. Lapse time is counted on Hackatime, and reviewers take any overlap with teardrop off so nothing counts twice.

Tokens

Token counts come from the usage records Claude Code and Codex save with each response. A Claude Code response that's written several times, or copied into a resumed session, counts once. Codex counts are taken from the increase in its running totals.

Claude Code

teardrop reads transcripts from $CLAUDE_CONFIG_DIR (which may list several folders), ~/.claude, and ~/.config/claude. It tells your prompts apart from tool results, compaction summaries, background notices, and subagent messages.

With hooks installed, Claude Code runs teardrop hook claude-code when a session starts or ends, when you send a prompt, and when Claude finishes. Each run appends one line to a local journal: the time, session, folder, and the prompt's word counts and fingerprint, never its text. If Claude Code deletes a transcript, the journal still has that session.

Codex

teardrop reads rollouts from $CODEX_HOME or ~/.codex, in both sessions and archived_sessions, including compressed .jsonl.zst files. It handles both the older and the current (0.147 and later) log formats. Subagent and reviewer sessions never count as your prompts. No hooks are needed.

Amp

Amp keeps threads on its servers, so teardrop setup (or teardrop setup amp for Amp alone) offers to write a plugin to ~/.config/amp/plugins/teardrop.ts. It records when a thread starts, when you send a prompt, and when Amp finishes, in the same journal as the Claude Code hooks. New Amp threads load it automatically; in open ones, run plugins: reload.

Note

Amp threads that run in Amp's cloud orbs are not on your machine, so a local teardrop can't see them.

Set up with a prompt

The dashboard's setup steps include a prompt to paste into Amp or Claude Code, with your server and sync key already filled in. The agent installs teardrop, runs teardrop setup -yes to add the hooks and the plugin without stopping to ask, connects the computer, and shows you the result. -yes is the part an agent can't do on its own, since setup otherwise asks before changing any settings. Because the prompt holds your sync key, make a new key under Settings, Setup if you'd rather not leave it in that thread.

Other tools

A VS Code extension (for Copilot, Cursor, and hand-written code) and a browser extension (for web chats like ChatGPT) are planned. Follow progress on GitHub.

Lines of code

For each project the report shows the lines agents changed (AGENT LINES), how many of the added lines later turned up in your commits (KEPT), and the lines your own commits added (COMMITTED). The code itself is not kept.

Sync and submit

teardrop sync uploads your signed counts to your account: time blocks, prompt and skipped-prompt counts, tokens, and line counts. It never uploads text. The first time, copy the command from Settings on the website. It looks like this:

teardrop sync -server https://your-site -key tdk_…

teardrop remembers the server and the key, so later it's just teardrop sync, and hooks sync in the background every 15 minutes. The key can only upload stats. If the server answers that it needs your sync key, run the command from Settings again.

teardrop submit <project> sends a project's hours for review together with the full chat logs behind them: your prompts, the agent's replies, and its code changes. It asks before uploading; -o file writes the submission so you can read it first. The server refuses a submission whose logs were changed after signing, or that claims a block no log backs, and recomputes the hours from the logs itself. You can submit a project again as it grows; time an earlier submission already covered is credited once. Add your Lapse sessions with -lapse <link>,…; time they also cover is taken off, since Hackatime already counts it.

Your stats on the website are visible to you and to admins. Deleting your account, under Settings, removes them; admins keep your Slack ID and a record of what your computers reported, without project names. Submissions and their chats are visible only to admins, who review them at /admin on the review server. To host either, see Running a server.

Running a server

There are two parts, and you can run either without the other:

PartWhat it doesWhere it runs
The websiteAccounts, sign-in, synced stats, and the dashboard.Cloudflare Workers, with its data in a D1 database.
The review serverTakes teardrop submit, recomputes the hours from the chat logs, and serves the review pages.Any machine that stays on, such as Fly.io.

The website, on Cloudflare

The Worker is in the worker folder of the repository and serves the pages in site. You need a Cloudflare account and Node.js 22 or later.

To try it on your computer first:

cd worker
npm install
cp .dev.vars.example .dev.vars
npm run dev

.dev.vars signs every visitor in as the Slack user ID in DEV_LOGIN, which only works on localhost. Open the address it prints and follow the setup steps on the dashboard.

To put it online, connect the repository to Cloudflare. Nothing needs to be installed or signed in on your computer.

  1. In the Cloudflare dashboard, open Workers & Pages, then Create, then Import a repository. Choose your fork of the repository.
  2. Name the Worker teardrop, set the root directory to worker, the build command to npm ci, and the deploy command to npm run deploy. Save and deploy. The first deploy creates the D1 database and its tables. It runs without the secrets, and the site says it is not set up yet.
  3. Create a Hack Club Auth app as in Set up sign-in below, with the openid, profile, and slack_id scopes and https://<worker>.<your-subdomain>.workers.dev/auth/callback as its redirect URI. Cloudflare shows the address under the Worker's Settings, Domains & Routes.
  4. Under the Worker's Settings, Variables and Secrets, add these as secrets: SESSION_SECRET (any long random text), HCA_CLIENT_ID, HCA_CLIENT_SECRET, and ADMINS. Deploying again, which a push to the branch does, keeps them.

If the build fails on permissions for D1, open the Worker's Settings, Builds, and give its API token D1 Edit access.

To deploy from your computer instead, run npx wrangler login in worker, then npm run deploy, and add the secrets in the dashboard or with npx wrangler secret put <NAME>.

SettingMeaning
SESSION_SECRETSigns sign-in cookies. Changing it signs everyone out.
HCA_CLIENT_ID, HCA_CLIENT_SECRETYour Hack Club Auth app.
ADMINSSlack user IDs of the people who can review, separated by commas. They get a Review link in the top bar and the account menu, which lists everyone. From there an admin can look anyone up by Slack ID and read their computers and a log of every report they sent. Each log entry opens to show what the report held and which days and projects changed. A computer's history, its latest report in full, and the whole log as a JSON download are on the same page.
REVIEW_SERVEROptional, in wrangler.jsonc. The address of your review server. With it set, teardrop submit works against the website's address, and submissions need a sync key.

To change a secret later, edit it in the dashboard. For your own domain, add a custom domain to the Worker and use it in the redirect URI. Cloudflare accepts uploads of up to 100 MB, so a larger submission has to go to the review server directly.

The review server

The review server is the same teardrop binary. It keeps everything as files in one folder, so it needs a machine that stays on and a disk that lasts; Cloudflare Workers can't host it.

Try it on your computer

teardrop server -addr 127.0.0.1:8080 -dev-login U012ABCDEF

-dev-login signs every visitor in as that Slack user ID without Hack Club Auth, and only works on a localhost address. Open http://127.0.0.1:8080/admin, then send it something from another terminal with teardrop sync -server http://127.0.0.1:8080.

Set up sign-in

  1. Open Developer Apps on auth.hackclub.com and create an app with the openid and slack_id scopes.
  2. Add https://your-server/auth/callback as its redirect URI.
  3. Copy the app's client ID and client secret.
  4. Collect the Slack user ID of each admin: in Slack, open their profile, choose ⋮, then Copy member ID.

Run it

TEARDROP_ADMINS=U012ABCDEF,U034GHIJKL \
TEARDROP_HCA_CLIENT_ID=... TEARDROP_HCA_CLIENT_SECRET=... \
teardrop server -addr :8080 -data /var/lib/teardrop -public-url https://your-server
SettingMeaning
TEARDROP_ADMINSSlack user IDs of the people who may review, separated by commas. Only they can open /admin.
TEARDROP_HCA_CLIENT_ID, TEARDROP_HCA_CLIENT_SECRETThe Hack Club Auth app from step 2.
-public-urlThe address people reach the server at. Also read from TEARDROP_PUBLIC_URL.
-addrAddress to listen on. Default :8080.
-dataFolder for accounts, submissions, and the sign-in key. Default teardrop-data. Back it up.
-max-submission-mbLargest submission accepted. Default 256.

Put it behind HTTPS, such as a reverse proxy that sets X-Forwarded-Proto. Run one copy only: two servers sharing a data folder would overwrite each other. On start, the log says if admins or sign-in are not set up.

Deploy to Fly.io

The repository has a Dockerfile and a fly.toml. With flyctl installed and signed in, from a clone of the repository:

  1. Pick an app name and put it in fly.toml, both as app and in TEARDROP_PUBLIC_URL. Then run fly apps create <app>.
  2. Create the disk: fly volumes create teardrop_data --region iad --size 1.
  3. Add https://<app>.fly.dev/auth/callback as a redirect URI in your Hack Club Auth app.
  4. Set the secrets: fly secrets set TEARDROP_ADMINS=... TEARDROP_HCA_CLIENT_ID=... TEARDROP_HCA_CLIENT_SECRET=....
  5. Deploy: fly deploy --build-arg VERSION=v0.4.1 --ha=false. --ha=false keeps Fly from starting a second machine.

Check it with fly logs. For your own domain, run fly certs add <domain>, then change TEARDROP_PUBLIC_URL and the redirect URI to match.

Point people at it

With REVIEW_SERVER set on the website, people need nothing more: teardrop submit goes through the website they already sync to. Without the website, each person runs this once:

teardrop sync -server https://your-server

Reviewing

/admin lists submissions. Each one shows the hours the account claimed, the hours the server recomputed from the logs, and every chat with the time between messages. Paste the project's Lapse or Lookout sessions there and the time they overlap is taken off. Time an earlier submission of the same project covered is taken off as well. /admin/accounts lists every account that has synced.

Privacy

teardrop reads timestamps, token counts, line counts, and working folders from your logs. Prompt text is only scored in memory to count recognized words; it is never stored or printed, and sync never uploads it. Your chat logs leave your computer only when you run teardrop submit and confirm.

Troubleshooting

“No Claude Code or Codex sessions found”

Run teardrop setup to see where teardrop looked. If your logs live elsewhere, such as inside WSL on Windows, pass -claude-dir or -codex-dir. Try -since 30d if your last session was more than a week ago.

“teardrop: command not found”

Open a new terminal so the PATH change applies. On Windows, restart any terminal that was open during install.

“skipped N log files that could not be read”

Run teardrop -verbose to list them. Usually they are files a tool is still writing, and the rest of the report is unaffected.

My hours look too low or too high

Compare ENGAGED with how long you think you worked, and please open an issue with the numbers.

Uninstall

Run teardrop setup -remove-hooks first. It removes the Claude Code hooks and the Amp plugin and leaves your other settings as they were. Then delete the teardrop binary and, if you want, the journal folder.
